## 1. วิธีที่ใช้ (และทำไมไม่ใช้ SIFT/ORB)

แนวทาง SIFT/ORB จับคู่ GISTDA basemap กับ Sentinel-2 true color **ใช้ไม่ได้** — ตรวจภาพแล้วพบว่า basemap ของแผนที่ GISTDA เป็น **แผนที่เวกเตอร์** (เส้นถนน/แม่น้ำ/ขอบเขต
สีเทาอ่อนบนพื้นขาว) ไม่ใช่ภาพถ่ายดาวเทียม · SIFT/ORB ต้องการ texture ของภาพถ่ายทั้งสองฝั่ง
· อีกทั้ง Sentinel-2 วันที่ 2 ต.ค. มีเมฆ ~52% (และวันน้ำสูงสุด 27 ก.ย. เมฆ 100%)

**วิธีที่ใช้จริง: อ่าน graticule ที่พิมพ์กำกับบนแผนที่** — แม่นและตรงไปตรงมา ไม่ต้องพึ่ง feature matching

พบว่าแผนที่นี้เป็น **plate carrée (องศาสี่เหลี่ยม)** ไม่ใช่ UTM:
px/°lon = 6390.0 · px/°lat = 6387.0 → **ต่างกัน 0.05%** (ถ้าเป็น UTM ที่ละติจูดนี้จะต่างกัน ~2.5%)

## 3. Affine (lon,lat → พิกเซล)

```
x = 6390.006390 * lon + 0.000000 * lat - 642218.645
y = 0.000000 * lon - 6387.006387 * lat + 93524.089
```
- **off-diagonal = 0** → ไม่มี rotation/shear
- สเกล: **16.89 ม./px (lon) · 17.31 ม./px (lat)** → 1 px = 292.3 ตร.ม.
- residual ที่ GCP = 0.0 px ทั้ง 4 จุด

## 4. การตรวจสอบ (3 ทาง + negative control)

| การตรวจ | ผล | เกณฑ์ |
|---|---|---|
| **Chamfer** เส้นขอบจังหวัด OSM → เส้นประดำบนแผนที่ | median **0–1 px** · p90 6.6 px · 97% < 20 px | เทียบแนว feature matching: 55.7 px |
| **พื้นที่จังหวัด** ที่สเกลแผนที่ | **2,137 ตร.กม.** vs OSM 2,151 vs mask_province 2,143 | คลาด 0.3–0.4% |
| **หาค่า offset ที่ดีที่สุด** | (di=1, dj=3) px ≈ 0 | ยืนยันว่าไม่มี bias ค้าง |

**Negative control** (พิสูจน์ว่าเมตริก "ล้มได้" จริง ไม่ใช่ผ่านเพราะบังเอิญ):

| การเลื่อน | median | สัดส่วน <20 px |
|---|---|---|
| (0,0) | 1.0 px | 86.1% |
| (100,0) | 47.9 px | 20.5% |
| (0,100) | 43.1 px | 30.7% |
| (300,0) | 141.0 px | 8.6% |
| ring สุ่ม ±300 px | 97.1 px | 13.1% |

→ ระยะห่างเพิ่มขึ้นตามการเลื่อนอย่างชัดเจน แปลว่าค่า 0–1 px ที่จุด fit เป็นของจริง

## 5. สีน้ำท่วมบนแผนที่

- **น้ำท่วม = ฟ้าสด (vivid cyan)** · เกณฑ์ `B−R > 150 และ B > 200`
- มี **ชั้นฟ้าอ่อนอีกชั้น** (B−R 60–150) ครอบพื้นที่นอกจังหวัด — **ยืนยันแล้วว่าเป็นข้อมูลน้ำท่วมชุดเดียวกัน
  ที่เรนเดอร์อ่อนกว่า** เพราะรอยต่อเปลี่ยนสี**พอดีที่เส้นขอบจังหวัด** (ดู `_compare_s1_vs_gistda.png` ประกอบ
  และ crop รอยต่อ) · ชั้นนี้อยู่ในจังหวัดเพียง 26 ตร.กม.
- legend บนแผนที่มี 6 รายการ (ขอบเขตจังหวัด/อำเภอ ถนน แม่น้ำ แหล่งน้ำ อาคาร) — **ไม่มี swatch ของชั้นน้ำท่วม**
  จึงต้องแยกสีเอง

## 6. พื้นที่น้ำท่วม: แผนที่ vs ตัวเลขที่ GISTDA ประกาศ

| แหล่ง | ในจังหวัด |
|---|---|
| ตัวเลขบนแผนที่ (badge) | 237,500 ไร่ = **380 ตร.กม.** |
| ดึงจากภาพ (raw, thr 150) | 442.2 ตร.กม. = 276,357 ไร่ |
| ดึงจากภาพ (thr 90 + erode 1 px) | **381.5 ตร.กม.** ✓ |

**ข้อสรุป**: ตัวเลข 380 ตร.กม. ของ GISTDA **สอดคล้องกับแผนที่ที่วาด** เมื่อตัดพิกเซลขอบที่เกิดจาก
anti-aliasing ออก · การดึงดิบเกินจริง ~16% เพราะรูปแบบน้ำท่วมระดับแปลงนามีเส้นรอบรูปมหาศาล
(ทุกขอบแปลงฟุ้ง ~1 px) — **ไม่ใช่ความขัดแย้ง แต่เป็นผลของขอบภาพ**

## 7. เทียบกับ Sentinel-1 ของเรา

> 8 ต.ค. 69: สูตรพื้นที่ของสคริปต์นี้ถูกทำให้เป็นสูตรเดียวกับ canonical (`common.cell_km2` — GL-13) · GISTDA-extraction ในตาราง = 442.7→445.7 จากการปรับสูตร ไม่ใช่มาสก์เปลี่ยน

| ชุด | ในจังหวัด | F1 | precision | recall | IoU |
|---|---|---|---|---|---|
| **S1 2 ต.ค.** vs GISTDA | 364.5 vs 442.7 | **0.700** | 0.778 | 0.636 | 0.538 |
| S1 peak 27 ก.ย. vs GISTDA | 450.5 vs 442.7 | 0.645 | 0.642 | 0.649 | 0.476 |

ทดสอบแล้วว่า **F1 0.70 ไม่ใช่ผลของ co-registration** (ตัวเลข offset/erode ด้านล่าง = รอบกฎเก่า 5 ต.ค. — แนวสรุปเดียวกัน):
- หา offset ที่ดีที่สุด → (di=1, dj=3) px ≈ 0 (ได้ F1 0.730 เท่านั้น)
- เทียบที่ความละเอียดของแผนที่เอง (17 ม.) → F1 ≈ 0.70 เท่าเดิม
- erode ทั้งสองฝั่ง → F1 **ลด** (0.646) แปลว่าความต่างไม่ได้อยู่ที่ขอบ

**ข้อควรระวังในการตีความ**: แผนที่ GISTDA เป็น **ภาพรวมช่วง 28 ก.ย.–2 ต.ค.** ส่วน `flood_2oct_validated`
เป็น **pass เดียวของ 2 ต.ค.** → ไม่ใช่การเทียบแบบเดียวกัน (composite จะรวมน้ำที่ลดไปแล้วด้วย)
ความต่างเชิงพื้นที่มีลักษณะเป็นก้อนต่อเนื่อง (ไม่ใช่ noise):
GISTDA เท่านั้น = ตามแนวลำน้ำทางอีสาน + ก้อนใหญ่กลางพื้นที่ (อ.องครักษ์/บ้านนา)
