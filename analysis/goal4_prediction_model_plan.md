## 2. ข้อมูลที่ยังขาด — แยกตามผู้ให

### ก. ต้องขอจากหน่วยงาน (FOI/จดหมาย/ติดต่อ)

1. **ตารางเปิด-ปิดบานระบายเขื่อนขุนด่านฯ รายชั่วโมง** (สช.9) — ตัวแปรต้นทางสำคัญที่สุดที่ขาด ข้อมูลชดเชยที่มีคือรายวัน + ภาพถ่ายจริง 25–28 ก.ย. (366/225 ลบ.ม./วิ) · *ไม่มีตัวนี้โมเดล "ทำนายเชิงปฏิบัติการ" จะสมมติสถานการณ์เขื่อน ไม่ใช่รู้ล่วงหน้า*
2. **ฝนพื้นที่รายชั่วโมง/เรดาร์** (กรมอุตุนิยมวิทยา — ต้องขอ token หรือใช้บริการสาธารณะ) — เรดาร์ครอบคลุมดีกว่าเคาน์ตี้ · ชดเชยได้ชั่วคราวด้วย GPM IMERG (ดาวเทียม ครึ่งชั่วโมง ฟรี แต่หน่วง ~14 ชม. และความละเอียด 10 กม.)
3. **ภา่มิวิทยาแม่น้ำนครนายก (ระดับท้องน้ำ/มาตรวัดหน้าตัด)** (สช.9/โยธาธิการฯ) — จำเป็นเฉพาะถ้าจะทำโมเดลไฮดรอลิกจริง (HEC-RAS) · โมเดลเชิงข้อมูลไม่ต้อง
4. **Google Flood Hub API key** (ขอฟรีที่ goo.gle/floodhub-api หรือ forms) — เพื่อเทียบ/เอาโมเดล Google มาเป็น ensemble

## 3. รูปแบบโมเดลที่เสนอ (3 ระดับ เรียงตามความเร็วในการทำ)

> **ผลทดลองจริงแล้ว (5 ต.ค. 69 — ดู `goal4_model_v1_findings.md`)**: เทรนเทียบ 3 โมเดลบนข้อมูล 3 ปี (2567–69, ฝึก 8,040 ชม. / ทดสอบกลางเหตุการณ์ 312 ชม.) — **สูตรเส้นตรงชนะทุกระยะ** (RMSE เหตุการณ์ 28.9/96.7/145.0 ซม. ที่ +6/+24/+48 ชม.) สู้กับ persistence ได้เล็กน้อย และ**ชนะ ML (GBDT) ขาดลอย** เพราะ tree-based ทำนายนอกช่วงข้อมูลฝึกไม่ได้ (เหตุการณ์ท่วมใหญ่มี 1 ครั้งและอยู่ในชุดทดสอบ) · ข้อจำกัดกลาง: ไม่มีฝนพยากรณ์เป็นอินพุต ทุกโมเดลตามขาขึ้นไม่ทัน (พีคต่ำ 1.8–2.9 ม. ที่ +24/48 ชม.) → **คำตอบสำหรับผู้ใช้: โมเดลง่ายเพียงพอและเหมาะกว่า ณ ตอนนี้; ML ค่อยพิจารณาเมื่อสะสมเหตุการณ์ ≥5 ครั้ง + มีฝนพยากรณ์; DL ไม่จำเป็น**

**ระดับ 1 — โมเดลเชิงข้อมูล (เริ่มได้ทันทีเมื่อข้อมูล 15 นาทีครบ)**
- ตัวแปรทำนาย: ระดับ Ny.7 ย้อนหลัง (1–48 ชม.) · ระดับ/Q Ny.1B ย้อนหลัง (ต้นน้ำ เวลาเดินทาง ~5–8 ชม. ตรวจจาก cross-correlation) · ฝนสถานีสะสม 3/6/12/24/48 ชม. · ระดับท้ายน้ำท่าช้าง (backwater) · Outflow เขื่อนรายวัน
- ทำนาย: ระดับ Ny.7 ณ +6/+24/+48 ชม. · วิธี: เริ่ม Gradient Boosting (XGBoost/LightGBM) แล้วค่อยลอง LSTM · ทดสอบแบบ hold-out เหตุการณ์ (ฝึก มิ.ย.–19 ก.ย. / ทดสอบ 20 ก.ย.–4 ต.ค.)
- เกณฑ์วัด: ความคลาดเคลื่อนพีค (ซม./ชม.), จำนวนชม.เตือนล่วงหน้าก่อนแตะ 8.45 ม. (ระดับล้นตลิ่งเมือง), ชม.ที่ทำนายถูกว่าเหนือ/ต่ำกว่าเกณฑ์เตือนภัย
- เทียบ baseline 3 ตัว: คงที่ (persistence) · โมเดล Google Flood Hub (มีอนุกรมแล้ว — ข้อดี: เห็นเลยว่าโมเดลเราเหนือกว่าตรงไหน โดยเฉพาะช่วงที่เขื่อนปล่อยน้ำ) · ถดถอยเชิงเส้น

**ระดับ 2 — สมดุลมวลน้ำตามสถานการณ์เขื่อน** (ทำแล้วบางส่วนใน qa5 — ขยายเป็นเครื่องมือ what-if): ให้ผู้ใช้ป้อน "ฝนพยากรณ์ + แผนปล่อยน้ำ" → ประมาณระดับ Ny.7 และพื้นที่ท่วม (ใช้ความสัมพันธ์ระดับ↔พื้นที่จาก S1+DEM ที่มีแล้ว)

**ระดับ 3 — ไฮดรอลิกเต็มรูป (HEC-RAS 1D/2D)** — ต้องรอภูมิวิทยาแม่น้ำจากหน่วยงาน · คุ้มเมื่อต้องการคำนวณเชิงกฎหมาย/ผังเมืองจริงจัง

## 4. ข้อควรระวังเชิงจริง

- ข้อมูลฝึกมีเหตุการณ์ท่วมใหญ่แค่ 1 เหตุการณ์ → โมเดลจะแม่นช่วงต้น-กลางเหตุการณ์ แต่ควรระบุ "ช่วงล้นตลิ่ง" เป็นกรณีพิเศษ (ข้อมูลน้อย) · แก้ด้วยการเก็บข้อมูลไปข้างหน้าทุกฤดู + ขอข้อมูลย้อนหลังหลายปีเพิ่ม
- ฤดูแล้งระดับน้ำต่ำมาก → ฝึกแยกโหมดหรือใช้เฉพาะฤดูน้ำหลาก
- การ "ทำนาย" ที่มีค่าใช้สอยจริงต้องรวม**ฝนพยากรณ์** เป็นอินพุต (ไม่ใช่ฝนวัดจริง) — ระดับ 1 แรกๆ จะเป็น "nowcast" ก่อน แล้วต่อยอดเมื่อมีฝนพยากรณ์ (TMD/Rainfinder/GFS)
- ตำแหน่ง Ny.7 อยู่เหนือจุดบรรจบคลองที่มีปตร.ควบคุม — พฤติกรรมช่วงเปิด-ปิดปตร.อาจไม่เชิงเส้น ใส่สถานะปตร.คลอง (มีรายวันใน khundan-tele) เป็นตัวแปรช่วยได้
