## 3. รูปทรงร่องน้ำจริงที่ Ny.7

```
offset (ม.)   -60 ................. 0 ...... 50 ...... 100 ......... 150
                                 (R1)   (ท้องน้ำ)    (R2)
ระดับ (ม.รทก.) 6.94 → 8.21 | 7.06 ↘ 4.05 ↘ -2.40 ↗ 6.56 | 7.52 ↗ 8.92 ↘ 8.43

→ ขอบที่ราบซ้ายสุด (offset −60 ม.) สูง **6.94 ม.รทก.** — ต่างจาก BANKFULL เชิงประจักษ์ของโปรเจกต์

```

| ค่า | ผลสำรวจ |
|---|---|
| จุดต่ำสุด (ท้องน้ำ) | **−2.396 ม.รทก.** @ offset 50 |
| สันตลิ่ง/ตอม่อ **ซ้าย** (offset 0, R1 บน) | **8.213 ม.รทก.** → เทียบเกจ = **9.80 ม.** |
| สันตลิ่ง/ตอม่อ **ขวา** (offset 100, R2 บน) | **8.919 ม.รทก.** |
| ขอบน้ำ ณ วันสำรวจ | 2.624 ม.รทก. → กว้าง ~52 ม. |
| ระดับพีคเหตุการณ์ (โปรเจค) | **7.64 ม.รทก. (เกจ 9.23)** |

### 3.1 ข้อค้นพบที่สำคัญที่สุด: **พีคเหตุการณ์ไม่ล้นสันตลิ่งที่สถานีนี้**

พีค **7.64 ม.รทก. ต่ำกว่าสันตลิ่งซ้าย (8.213) อยู่ 0.57 ม.** และต่ำกว่าฝั่งขวา 1.28 ม.
→ **น้ำไม่เคยล้นสันตลิ่งที่หน้าตัดสถานี Ny.7 เลย** แต่ **เมืองท่วมจริง** (ข่าว: 40–50 ซม.)

อธิบายได้เพราะ **ตลิ่งซ้ายไม่ใช่คันดิน** — พื้นที่ถัดออกไปลาด **ลง** จาก 8.213 (offset 0) เหลือ 6.937 (offset −60)
พีค 7.64 จึง **ท่วมที่ราบน้ำท่วมถึง (floodplain) ฝั่งซ้ายช่วง offset −60 ถึงราว −25** แต่ไม่ข้ามสัน 8.213

**สอดคล้องกับข้อสรุปของโปรเจค** (`khundan_tele_findings.md` K3): *"ผิวน้ำพีค 7.6 ม.รทก. ทับพื้นที่เมือง 4–7 ม.รทก. → ความลึก 0.6–3.6 ม."* — และตอนนี้มี **รูปทรงจริง** มาอธิบายกลไกได้แล้วว่าทำไมน้ำถึงเข้าเมืองได้ทั้งที่ "ไม่ล้นตลิ่ง"

### 3.2 กระทบนิยาม "BANKFULL = 6.86 ม.รทก." ของโปรเจคอย่างไร

`docs/DATA_DICTIONARY.md:83` กำหนด "ระดับล้นตลิ่งเมือง = เกจ Ny.7 8.45 ม. (= ม.รทก. 6.86)" โดย **anchor เชิงประจักษ์** (ชั่วโมงที่ระดับข้ามค่านี้ตรงกับเวลาข่าวเริ่มท่วม)

เทียบกับผลสำรวจ:

| นิยาม | ระดับ |
|---|---|
| ต่ำสุดของพื้นที่ข้างเคียงในหน้าตัดสำรวจ (offset −60) | **6.937 ม.รทก.** (เกจ 8.53) |
| ค่าที่โปรเจคใช้ | **6.86 ม.รทก.** (เกจ 8.45) |
| สันตลิ่ง/ตอม่อจริง | 8.213 ม.รทก. (เกจ 9.80) |

→ ค่าของโปรเจค **ตรงกับ "ระดับต่ำสุดของที่ราบข้างเคียง" ภายใน 8 ซม.** ถือว่า **นิยามใช้ได้** แต่ **ชื่อเรียกควรแก้**:
**6.86 ม.รทก. ไม่ใช่ "ระดับล้นตลิ่ง" (bank overtopping) แต่เป็น "ระดับเริ่มท่วมที่ราบน้ำท่วมถึง" (onset of floodplain inundation)**
ความต่างนี้สำคัญ เพราะถ้าอ้างว่า "ล้นตลิ่ง" แล้วมีคนไปเทียบกับสันตลิ่งที่สำรวจได้ (9.80 ม.เกจ) จะดูขัดกัน

## 4. ตรวจไขว้ rating curve กับรูปทรงจริง — ✅ **rating curve สอดคล้องกับเรขาคณิต**

> ⚠️ **ระวังการนับเส้นรอบเปียก** — ถ้านับ "ผิวน้ำอิสระ" เป็นขอบเปียกด้วย
> R จะต่ำเกิน ~2 เท่า → Q ต่ำเกิน 1.63 เท่า และได้ n ต่ำผิดปกติ (~0.0268) ซึ่งเป็นสัญญาณว่าคำนวณผิด
> · ค่าที่ถูกคือ **n = 0.0437** · รายละเอียดเต็ม: **`analysis/rid_cross_section_stage_rating.md`**

โปรเจคใช้ `Q = 242·(h−4.55)^0.66` (h = ม.รทก.) · คำนวณที่ Ny.7 ระดับพีค 7.64 ม.รทก.:

| วิธี | Q (ม³/วิ) |
|---|---|
| rating curve ของโปรเจค | **510** |
| Manning `Q=(1/n)·A·R^⅔·√S` (n=0.030) | 742 |
| Manning (n=0.035) | 636 |
| Manning (n=0.040) | 557 |
| Manning (n=0.045) | 495 |
| **n ที่ทำให้ Manning = rating curve** | **0.0437** |

ใช้ S = 9 ม./28 กม. = 3.2×10⁻⁴ · A = 524 ม² · P = 144 ม. (ขอบเปียกแข็ง) · **R = 3.65 ม.**

**สรุป:** n = 0.0437 อยู่ในช่วงปกติของแม่น้ำที่ราบลุ่ม (0.04–0.07) → **ไม่มีหลักฐานว่า rating curve สูงเกิน**
และค่านี้ **คงที่ตลอดช่วงระดับ** (0.044–0.048 ที่ 5–9 ม.รทก.) ซึ่งเป็นสิ่งที่ควรเกิดถ้า rating curve มีรูปทรงถูก
(การทดสอบช่วงนี้ต้องใช้หน้าตัดปี 2565/2566 ที่กว้างกว่า เพราะหน้าตัดปีล่าสุดถูกตัดที่ขอบช่วงพีค — ดู §4.2)

### 4.1 หมายเหตุ Ny.1B — สถานีที่ค่า Q ยังน่าสงสัย

ที่ Ny.1B พีค 11.07 ม.รทก. น้ำอยู่ **เหนือสันตลิ่งทั้งสองฝั่ง** และล้นออกนอกช่วงสำรวจทั้งสองข้าง
→ หน้าตัดจมหมด · n ที่ต้องใช้เพื่อให้ตรง rating (834) = **0.0237** — ต่ำผิดปกติ
มีข้อสังเกตเรื่อง **Q = 668.6 ม³/วิ** ที่ยังเป็น `[I]`
→ **ยืนยันว่าควรลดความเชื่อถือค่า Q ของ Ny.1B ลง หรือกำกับ error bar ให้ชัด**

### 4.2 หน้าตัดหลายปี + การทดลองต่อปลายด้วย DEM

- **4 ปีในไฟล์เดียว** (2565/2566/2567/2568): ท้องน้ำกัดลึก −1.979 → −2.396 ม.รทก. (0.42 ม. ใน 2 ปี)
- ปีที่ **กว้างกว่า** (2565/2566: −100..200) ให้ Q **ต่ำกว่า** (590–595 vs 636)
  → **การถูกตัดที่ขอบสำรวจไม่ใช่สาเหตุของช่องว่าง**
- **ต่อปลายด้วย Copernicus DEM: ทดลองแล้ว ปฏิเสธ** — DSM คลาดจากหน้าตัดสำรวจ 3.2 ม. RMS
  *ในช่วงทับซ้อน* (ดู `rid_cross_section_stage_rating.md` §3)

**ควรทำต่อ (เรียงตามความคุ้มค่า)**
1. ✅ **ผลลบ:** ขยายหน้าตัดด้วย Copernicus DEM ใช้ไม่ได้ (DSM คลาด 3.2 ม. RMS ในช่วงทับซ้อน) · ดู `rid_cross_section_stage_rating.md` §3
2. ✅ หน้าตัดปีอื่น **อยู่ในไฟล์เดียวกันอยู่แล้ว** (2565/2566/2567/2568 — คอลัมน์ R:S/T:U/V:W/Z:AA) ไม่ต้องโหลดเพิ่ม → ท้องน้ำกัดลึก 0.42 ม. (2566→2568)
