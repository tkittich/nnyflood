## 1. หลักการถ่ายทอดจากนครนายก

วิธีการที่จะถ่ายทอดไม่ใช่สคริปต์ แต่เป็น**ลำดับคำถามเดิม 4 ข้อ** (`docs/ANALYSIS_PLAN.md`):

1. ฝนรุนแรง/ผิดปกติแค่ไหน (คาบคืน, ครอบคลุมลุ่มบน vs ที่ราบ)
2. การบริหารเขื่อนเป็นไปตามมาตรฐาน (rule curve) หรือไม่ — วันที่เกิน/ปริมาตรเกิน/จังหวะปล่อย
3. ฝน vs การปล่อย อธิบายระดับน้ำในพื้นที่ได้เท่าไร (attribution + lag propagation)
4. โมเดลทำนาย + สถานการณ์บริหารทางเลือก

และกติกาเดิมทุกข้อ: จุดยืนเป็นกลางตามหลักฐาน · ทุกตัวเลขมีแหล่งอ้างอิง ·
ทุกการดึงข้อมูลลง manifest + SHA-256 · นิยาม "เหตุการณ์" ของแต่ละลุ่ม**เขียนไว้ก่อนดูผล** (pre-registration)

## 3. เครือข่ายประตูน้ำทั่วประเทศ (เพิ่ม 10 ต.ค. 2569 — probe API จริงแล้ว)

เป้าหมายย่อยใหม่: เก็บข้อมูลประตูระบายน้ำ (ปตร.) ทั้งประเทศ — **รวมลุ่มที่ไม่มีเขื่อน** —
แล้วรวมเขื่อน + ปตร. + จุดวัด + คลองเป็น**กราฟเครือข่ายเดียวระดับชาติ** ที่มาเชิงคุณภาพ:
โซนน้ำขังนานสุดของนครนายก (242 ตร.กม. ≥6 วัน) คือท้ายลุ่มที่ไม่มีปตร./จุดวัดใหญ่ควบคุม —
คำถาม "เครือข่ายจุดไหนเป็นคอขวด/จุดบอด" ถามได้ทั้งประเทศ

**ผล probe 10 ต.ค. 2569 — ดึงตรงได้ทั้งหมด ไม่ต้อง FOI** (base เดียวกับ data/02 ·
raw: `2026-10-09_watergate_load.json` / `2026-10-09_canal_waterlevel.json` / `2026-10-09_flow.json`):

| Endpoint | ได้อะไร | ผล probe |
|---|---|---|
| `public/watergate_load` | snapshot ล่าสุดทุก ปตร.: ระดับหน้า/หลังประตู + `pump_on`/`pump` (เครื่องสูบ) + `floodgate_open`/`height` (เปิดบาน) + พิกัด/ลุ่มน้ำ/สังกัด | **2,315 แห่ง / 24 ลุ่มน้ำ** — สสน. 1,144 · ชป. 734 · พพภ. 213 · สนน กทม. 74 · ไม่ระบุ 148 |
| `public/watergate_graph` (`station_id`+`start_date`+`end_date`) | ย้อนหลังราย **10 นาที**: หน้า/หลังประตู + discharge + `critical_level`/`ground_level` | ทดสอบ ปตร.บางระจัน (id 492329) 20 ก.ย.–9 ต.ค. 69 มีค่าจริง ✓ — ช่วงย้อนหลังสุดยังไม่ทดสอบ |

ข้อจำกัดที่เห็นตอนนี้: `pump_on`/`floodgate_open` เป็น**สถานะปัจจุบัน** — วันปกติเป็น null,
มีค่าเมื่อกำลังเดินเครื่อง/เปิดบาน · **ประวัติเปิด-ปิดบาน/เดินเครื่องย้อนหลังไม่มี endpoint**
(ปัญหาเดียวกับตารางบานขุนด่านฯ → FOI ระดับชาติ) · แถวไม่ระบุสังกัด 148 จุด — QA ต่อจุดก่อนใช้

**ข้อมูลที่ควรเก็บเพิ่มเพื่อ "เครือข่ายทั้งประเทศ"** (ตอบคำถามผู้ใช้ 10 ต.ค.):

1. **ทะเบียน+สแนปช็อต ปตร. 2,315 จุด** (`watergate_load`) — รายวันช่วงหน้าฝน (ขยาย cron archive เดิมได้)
2. **กราฟ 10 นาที** เฉพาะ ปตร. ในลุ่มสนใจ — ทั้งประเทศราย 10 นาทีใหญ่เกิน; snapshot รายวันพอสำหรับภาพรวม
3. **คลอง 282 จุด + อัตราไหล 55 จุด** — latest รายวัน
4. **ระดับเตือน/วิกฤตต่อจุด** (มีใน metadata ของ `watergate_graph`/`waterlevel_graph`) —
   ใช้เป็นเกณฑ์ screen เหตุการณ์แบบเป็นกลางทั่วประเทศ (ไม่ต้องเดา threshold ต่อลุ่ม)
5. **โครงกราฟเชื่อมโยง**: HydroSHEDS/HydroBASINS (เปิด, ระดับโลก) ให้ topology ลำน้ำ+ขอบลุ่ม ·
   OSM waterway คลองสายรอง → ผูก ปตร./จุดวัดเข้า node ด้วยพิกัด (snap ≤ รัศมีที่ประกาศล่วงหน้า)
6. **ขอบเขตลุ่มน้ำทางการ กช.** (22 ลุ่มน้ำ + ลุ่มสาขา) — ติดป้าย node ให้ตรงศัพท์ราชการ
7. **GISTDA น้ำท่วมราย pass ทั้งประเทศ** (ไม่มี API — มนุษย์) — ทำเครื่องหมายว่า node ไหนอยู่ในพื้นที่ท่วมจริง
8. **สถานีสูบน้ำ (pump)** — field มีใน ปตร. อยู่แล้ว; ทะเบียนโครงการสูบเฉพาะ ยังต้องหาแหล่ง (เฟสถัดไป)

## 8. ข้อจำกัดความเปรียบเทียบ — เขียนไว้ตั้งแต่ต้น

1. **นครนายกได้ natural experiment พิเศษ** (วันน้ำสูงสุดฝนท้องถิ่น = 0) — ลุ่มอื่นอาจไม่มี
   วิธี attribution ต่างกันได้ต่อลุ่ม แต่ต้องระบุให้ชัดและอย่าเทียบตัวเลขข้ามวิธี
2. **นิยามเหตุการณ์ pre-register** — หน้าต่างเวลา = จาก peak ระดับน้ำจุดเป้าหมาย ± n วัน กำหนดก่อนดูฝน/การปล่อย
3. **datum/คุณภาพจุดวัดต่อลุ่ม** — นครนายกเจอ datum 9 จุดเปลี่ยนกลางเดือน + สถานีรหัสเก่าคืน null;
   ทุกลุ่มต้อง QA ก่อนใช้ (ตาราง Δ แบบ all_stations_network)
4. **กฟผ. ≠ ชป.** — วัตถุประสงค์เขื่อน (ไฟฟ้า vs ชลประทาน), rule curve, ระเบียบรายงานต่างกัน;
   เปรียบเทียบได้ในเชิงคำถาม ไม่ใช่เชิงค่าตัวเลขตรง ๆ · **ปตร. ก็ซ้อนกัน**: สสน./ชป./พพภ./กทม.
   เก็บสถานะคนละรูปแบบ — 148 จุดไม่ระบุสังกัด
5. **ลุ่มหลายเขื่อน** (แม่กลอง, ปิง, น่าน, ชี, มูล) — attribution ต่อเขื่อนหรือรวมกลุ่มเขื่อน ต้องเลือกและประกาศล่วงหน้า
6. **เครือข่าย ปตร. เทียบไม่ได้เชิงการเดินเครื่อง** — API ให้เฉพาะสถานะปัจจุบัน ไม่มีประวัติบาน/เครื่องสูบ;
   ห้ามสรุป "เปิดช้า/เร็ว" จากข้อมูลสแนปช็อต (เฉพาะ N3 เชิงระดับน้ำ กับ N1/N2 เชิงเรขภาพ ที่ทำได้ก่อน FOI)
7. โมเดล L3 พึ่ง rating/stage จุดเดียวเหมือนเดิม — อย่าอ่านละเอียดเกินกรอบ ±rating ที่ประเมินได้
