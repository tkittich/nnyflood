# การตรวจทานกฎหมายก่อนเผยแพร่: หมิ่นประมาท + PDPA

> ตรวจเมื่อ 8 ต.ค. 2569 ก่อน publish · ขอบเขต: รายงาน 2 ฉบับ + ข้อมูลใน repo ที่จะเผยแพร่
> (เอกสารนี้เป็นการตรวจทานเชิงป้องกันตัวโดยทีมจัดทำ ไม่ใช่คำแนะนำทางกฎหมายจากทนายความ)

## 1. กฎหมายหมิ่นประมาท (ประมวลกฎหมายอาญา ม.326–329 · พ.ร.บ.คอมพิวเตอร์ ม.14)

**หลักกฎหมายที่เกี่ยว**
- ความผิดหมิ่นประมาทต้องมี "ผู้เสียหาย" ที่ถูกทำให้เสื่อมเสียชื่อเสียง — **หน่วยงานราชการเป็นผู้เสียหายไม่ได้**
  (ศาลฎีกาว่าหน่วยงานของรัฐต้องรับการตรวจสอบ/วิจารณ์ในทางสาธารณะ) — จึงไม่มีสิทธิฟ้องคดีอาญาหมิ่นฯ
- พ.ร.บ.คอมพิวเตอร์ ม.14 ต้องเป็นการป้อน **ข้อมูลอันเป็นเท็จ** — ข้อมูลจริงที่มีหลักฐานจึงไม่เข้าข่าย
- ม.329 ให้ยกเว้น: การวิจารณ์/ติชมในทางเป็นธรรม โดยสุจริต เกี่ยวกับ **บุคคลที่อยู่ในเรื่องเกี่ยวกับสาธารณะ**
  (ข้าราชการในการปฏิบัติหน้าที่ เข้าข่าย) และเพื่อประโยชน์สาธารณะ

**ผลการตรวจจริง — ใคร/หน่วยงานไหนถูกกล่าวถึง**
| ถูกกล่าวถึง | ลักษณะ | ความเสี่ยง | หลักฐานป้องกัน |
|---|---|---|---|
| กช. / สช.9 / โครงการเขื่อน | วิจารณ์ "แผนไม่มีกลไก URC" "เหนือ URC 36 วัน" | **ต่ำมาก** — หน่วยงานราชการฟ้องไม่ได้ + เป็นข้อมูลจริงอ้าง API/เอกสารได้ + รายงานยืนยันว่า "ปฏิบัติตรงแผนของตนเองทุกประการ" (วิจารณ์ระบบ ไม่ใช่ตัวบุคคล) | ฉบับวิชาการ §3, §4D · FAQ "แล้วช่องโหว่อยู่ตรงไหน?" |
| รมช.มหาดไทย (สั่งปิดประตู 27 ก.ย.) | รายงานข้อเท็จจริงเชิงเวลาเท่านั้น (มีเฉพาะใน `report/รายงาน.md` — เอกสารทำงาน) | ต่ำ — เป็นบุคคลสาธารณะในการปฏิบัติหน้าที่ + มีประกาศของเขื่อน "รับคำสั่ง มท." เป็นหลักฐาน (data/01) | manifest data/01 |
| รศ.ดร.สิทธางค์ พิไลลักษณ์ | อ้างคำวิจารณ์ของเขาเองจากรายการสาธารณะ (Thai PBS 28 ก.ย.) | ต่ำ — อ้างคำพูดสาธารณะของเจ้าตัวอย่างถูกต้อง + ระบุแหล่ง | data/05 · รายงาน ง |
| เพจ "ที' ลมฟ้าอากาศ" | ระบุจุดแข็ง (พยากรณ์ตรง) + ข้อจำกัด (ไม่มีสถิติความแม่น, แก้ไขโพสต์บ้าง) | **ต่ำ–ปานกลาง** — เป็นหน้า/นิติบุคคลที่ฟ้องเรื่องธุรกิจได้ แต่ข้อเท็จจริงทุกข้อเป็นสิ่งที่เพจเผยแพร่เอง (ป้าย "แก้ไขแล้ว") และเป็นการวิจารณ์เชิงสร้างสรรค์ในเรื่องสาธารณะ | data/11 manifest + qa4 |

**มาตรการที่ฝังอยู่ในรายงานแล้ว (คงไว้)**: แยก fact/interpretation/assessment ทุกข้อ · หัวข้อ "แล้วช่องโหว่อยู่ตรงไหน?"
(เดิม "แล้วใครผิด?" — แก้หัวข้อ 8 ต.ค. 69 ให้ไม่ตั้งกรอบหาคนผิด) ระบุชัด "ไม่ใช่ตัดสินความผิดบุคคล" · ยืนยันด้านบวกของหน่วยงานด้วย (ปฏิบัติตรงแผน, เตือนล่วงหน้า, งดส่งน้ำวิกฤต) ·
คำเตือน AI/ตรวจทานโดยผู้เชี่ยวชาญทุกฉบับ

## 2. PDPA (พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562)

**หลักกฎหมายที่เกี่ยว**
- ครอบคลุมเฉพาะ**ข้อมูลส่วนบุคคลของบุคคลธรรมดา** (หน่วยงานราชการ/นิติบุคคล/หน้าเพจในฐานะองค์กรไม่เข้าข่าย)
- ฐานยกเว้นความยินยอมที่เกี่ยว: **ม.24(ง)** — จำเป็นเพื่อการศึกษาวิจัย ประวัติศาสตร์ สถิติ หรือประโยชน์สาธารณะอื่น
  (ตามคู่มือ กสทช./กรมทรัพย์สินทางปัญญา มักกำหนดเงื่อนไขเพิ่ม เช่น ปกปิดตัวตน) · ม.29 ·
  ประกาศ สคส. เรื่องมาตรการเก็บรวบรวมเพื่อการศึกษาวิจัย (ข้อมูลโพสต์เครือข่ายสังคมออนไลน์ — ต้องมีมาตรการแยก/ปกปิดตัวตน)
- สิทธิของเจ้าของข้อมูล: คัดค้าน (ม.32) ขอให้ลบ/ปกปิด

**ผลการตรวจจริง — ข้อมูลส่วนบุคคลใน repo ที่จะเผยแพร่**
| ไฟล์/เนื้อหา | ข้อมูลส่วนบุคคล | การจัดการ |
|---|---|---|
| รายงาน 2 ฉบับ | กล่าวถึงบุคคลธรรมดาชื่อจริงเพียงคนเดียว = รศ.สิทธางค์ (ข้อมูลบุคคลสาธารณะ เผยแพร่เองในสื่อ อ้างเชิงวิชาการอย่างเป็นธรรม) · เจ้าของโปรเจกต์ไม่ปรากฏชื่อ | ต่ำ — คงไว้พร้อมการอ้างอิง |
| data/06 (โพสต์/คำบรรยายประชาชน) | ข้อความ/ลิงก์โพสต์สาธารณะของ**เพจ** (ไม่ใช่บุคคล) — ไม่มีชื่อ/โปรไฟล์ผู้คน · **ภาพถ่ายประชาชนไม่ถูก track ใน git** | ต่ำ — คงไว้ + หมายเหตุ PDPA ใน manifest |
| data/11 tee_page/screenshots | ตรวจภาพจริง 4 ใบ: **พบส่วนติดต่อบัญชีผู้ใช้ (อวตาร/แถบข้าง/โฆษณาเฉพาะบุคคล)** | **แก้แล้ว**: crop ให้เหลือเฉพาะโพสต์หลักฐาน — ต้นฉบับเต็มย้าย `archive/screenshots_originals/` (gitignored) |
| data/01 fb/ig raw | JSON โพสต์ของเพจเขื่อน (fbid/ลิงก์/ข้อความ) — ไม่มีชื่อบุคคลที่สาม (ตรวจ keys ทุกไฟล์) | ต่ำ |
| ข้อความโพสต์ประชาชนที่อ้างในรายงาน | ไม่ระบุชื่อผู้โพสต์ (อ้างเฉพาะตำบล/ประเด็น) | ต่ำ |

**มาตรการคงเหลือที่แนะนำหลัง publish**: ระบุช่องทางติดต่อ (issue ของ repo) เพื่อให้เจ้าของข้อมูล
ร้องขอตรวจทาน/ลบ/ปกปิดได้ · ห้ามเพิ่มภาพถ่ายบุคคลเข้า repo ในอนาคจนกว่าจะประเมินแยก ·
ถ้ามีการร้องเรียน: ตอบสนองทันทีด้วยการปกปิดตัวตน/ลบ แล้วบันทึกใน manifest

## 3. สรุปความเสี่ยง

| เรื่อง | ระดับความเสี่ยง | เหตุผลหลัก |
|---|---|---|
| หมิ่นประมาทหน่วยงานราชการ | **ต่ำมาก** | ฟ้องไม่ได้ตามหลัก + ข้อมูลจริงอ้างแหล่ง + วิจารณ์ระบบไม่ใช่บุคคล + ให้ด้วยด้านบวก |
| หมิ่นประมาทบุคคล/เพจเอกชน | ต่ำ | อ้างคำพูดสาธารณะของเจ้าตัว + ข้อเท็จจริงที่เพจเผยแพร่เอง + จำกัดขอบเขต |
| PDPA (ข้อมูลบุคคลที่สามใน repo) | ต่ำ | ไม่มีชื่อบุคคลที่สามในไฟล์ที่ track · ภาพประชาชนไม่ถูกเผยแพร่ · screenshots ครอปแล้ว · ใช้ฐานม.24(ง) ประโยชน์สาธารณะ |
| PDPA (ตัวผู้จัดทำ) | เลือกได้ | เจ้าของโปรเจกต์ไม่ปรากฏชื่อใน repo — คงความเป็นนิรนามไว้ตามต้องการ |

ขอบเขตที่ยังไม่ครอบ: ความเสี่ยงทางแพ่ง (ชดใช้ค่าสินไหม ม.330–332) มีฐานป้องกันเดียวกัน
(ข้อมูลจริง+สุจริต+เป็นธรรม) แต่ถ้าต้องการความมั่นใจสูงก่อนเผยแพร่วงกว้าง ควรให้ทนายความตรวจซ้ำ
โดยเฉพาะหมวดข้อเสนอต่อภาครัฐ (E1–E7) ที่กล่าวถึงการปฏิบัติหน้าที่ของหน่วยงานโดยตรง
