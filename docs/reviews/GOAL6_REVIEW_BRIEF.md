## 3. ข้อจำกัดที่ประกาศไว้แล้วในรายงาน (ตรวจว่าพอหรือขาด)

1. เกณฑ์ critical ใน API คนละ datum กับอนุกรม (18 จุด SUSPECT — จัดชั้นไว้แล้ว)
2. ประวัติบาน/เดินเครื่องสูบไม่มีใน API ทุกสังกัด → attribution ระดับรายวันเท่านั้น
3. ฝน POWER กริด 0.5° รีดยอดฝนเบลอ (คาบคืนอ่านแบบชั้นล่าง)
4. S2 เมฆปิด = ตรวจยืนยันเชิงพื้นที่ทำไม่ได้ระลอกนี้ (S1 ยืนเรดาร์เดี่ยว + เวลา)
5. DEM กทม. ใช้เชิงคุณภาพเท่านั้น (ที่ราบ 1–1.5 ม.รทก. + ที่ดินทรุด)
6. อนุกรมรายชั่วโมงมีช่องว่าง (45–80% ต่อปี) — อย่า interp ข้ามช่องยาว
7. ฝน POWER ครบ 199 จุดแล้ว (10 ต.ค.) — แต่ยังเป็นกริด 0.5° ทั้งชุด · จุดวัดไกลกันที่พิกัดต่าง
   น้อยกว่าครึ่งกริดอาจแชร์ค่าเดียวกัน (เห็นใน MD: บางจุดต่างลุ่มมีค่าเท่ากัน) — ให้รีวิวว่า
   การสรุประดับ "ลุ่ม" ปลอดภัยแค่ไหนกับข้อจำกัดนี้

## 4. คำถามเฉพาะที่อยากได้ความเห็น

1. กฎ "เดินปีถอยจนว่าง 2 ปีต่อเนื่อง" พอสำหรับความลึกย้อนหลังไหม (เช่น C.2 ควรไปหาแฟ้ม กช. ก่อน 2019 จริงไหม?)
2. เทมเพลต URC แบบ "เดือน-วัน" — เสี่ยงอะไรถ้าเขื่อนไหนปรับ curve กลางช่วง (เช่น ปรับ URC ปี 2560 กับ 2569 ต่างกัน)?
3. การเทียบ 2554 vs 2569 ด้วยเขื่อนรายวันล้วน (ไม่มีระดับน้ำแม่น้ำ 2554) — ข้อสรุปไหนที่เกินหลักฐาน?
4. กทม. attribution สามทาง: มาสก์น้ำถาวร+DEM<1.2 ม. พอไหม หรือต้องใช้แหล่งอื่น (LiDAR/แผนที่ สนน.)?
5. นิยาม "เหตุการณ์" (หน้าต่าง 1 ก.ค.–9 ต.ค. คงที่ทุกลุ่ม) — ลุ่มที่พีค ส.ค. (ป่าสักลุ่มบน) จัดอย่างไรให้เป็นกลาง?
6. การผูก node→ลุ่มย่อย lev08 แบบ point-in-polygon พิกัด API ตรง ๆ (ไม่เลื่อนพิกัด) —
   จุดที่ผูกไม่ได้นับเปิดเผย (จุดวัด 0 · ปตร. 6) — เกณฑ์นี้โปร่งใสพอไหม หรือควรเติมวิธี snap สำรอง?
7. ข้อสรุป "ฝนติดอันดับ 1–3 ที่ 67/199 จุด" วาดเป็นภาพระดับชาติ — มีจุดอ่อนการนำเสนออะไร
   (เช่น จุดที่ค่าซ้ำกันเพราะแชร์กริด POWER จะทำตัวเลขฟูมิให้หนักขึ้นไหม)?
