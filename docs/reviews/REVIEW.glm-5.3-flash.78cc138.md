## 7. Overall System Suggestions & Consistency Recommendations

1. **Close the artifact-vs-status-doc loop automatically (would have caught F-01).** The recurring failure class is "status docs describe a deliverable that the built artifact lacks". A cheap permanent guard: after every `*_build_all.py` run, a small script asserts a handful of *claim markers* against the HTML files — e.g. Report 4 must contain "8.1" + `matrix_anchored` counts whenever `compound_flood_risk_summary.json` has the key; Report 3 limitation 7 must contain a sentence per sensitivity JSON that exists. This is the same pattern as `write_verification.py` but for presence-of-section rather than pass/fail.
2. **Make retired ledgers data-driven everywhere (F-06)** — extend the goal-6 `retired.retired_values` pattern to goal-7 canonical, and have `test_no_retired_values` read it. Every future retirement then automatically updates the guard instead of requiring a hand-edited string list.
3. **Single-divisor policy for derived economics (F-03)**: when a lifecycle divisor is an assumption, either (a) derive it in the same script from the sourced statistic it approximates, or (b) force the assumption label into the rendering layer (the token/engine already supports annotations). A registry note that never reaches the reader is not enough under this project's own conventions.
4. **Harmonize the two completeness tools (F-02)** and treat a red `verify_all` as an unconditional stop-line: F-01 survived at least two rebuild cycles because attention was absorbed by a known-red chain.
5. **Methodological (hydraulics)**: the remaining physical-uncertainty frontiers are unchanged from round 7 — 1-D routing needs the RID chainage and eventually a diffusive-wave/floodplain variant before travel-time language strengthens; the compound matrix needs multi-year C.12 data before c₁/exponent calibration; the 2-D model's (f, k) unidentifiability is honestly reported and should stay a diagnostic until a second event or gauge data (NYK000 gap 30 Sep–5 Oct) permits splitting the pair. None of these blocks the current exploratory framing — the framing discipline is the project's strongest asset; keep pre-registration as the default for any change that can move a published number.
