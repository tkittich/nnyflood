## บทสรุปผู้บริหาร

**น้ำท่วม อ.เมือง นครนายก 26–29 ก.ย. 2569 เกิดจากฝนตกหนักต่อเนื่องเฉพาะแถบ 18 วัน (1,058–1,416 มม. ในแนวเชิงเขา–ที่ราบตอนบน) เป็นสาเหตุหลัก** คลื่นน้ำหลากคืนวันที่ 26 ทำให้แม่น้ำล้นตลิ่งกลางดึก และระดับน้ำสูงสุดที่ตัวเมือง (9.23 ม. ณ จุดวัด Ny.7, 27 ก.ย. 10:00 น.) เกิดขึ้น**ก่อน**ที่เขื่อนขุนด่านปราการชลจะเร่งการระบายสูงสุด

**การบริหารเขื่อนมีบทบาท "ยืดความรุนแรงและระยะเวลา" ในช่วงท้ายของเหตุการณ์ ไม่ใช่ต้นเหตุของน้ำสูงสุด** — แต่การปล่อยน้ำหนักสุด 31.66 ล้าน ลบ.ม./วัน (366 ลบ.ม./วินาที) ในวันที่ 27 ตรงกับช่วงน้ำท่วมขังสูงสุด ทำให้ระดับน้ำ ≥8 ม. (ระดับท่วม) ค้างยาวนานถึง **79 ชั่วโมง**

**ประเด็นเชิงระบบที่สำคัญที่สุด (F-SC2)**: น้ำเก็บเขื่อนอยู่เหนือ Rule Curve บนต่อเนื่อง **36 วัน** (30 ส.ค.–4 ต.ค.) ขณะที่ "ตารางระบายน้ำเดือน ก.ย. 69" ซึ่งโครงการฯ ประกาศไว้เองกำหนดเพียงการส่งน้ำเกษตร 10–14 ลบ.ม./วินาที **โดยไม่มีบทระบายลดระดับแม้แต่บรรทัดเดียว** — โครงการปฏิบัติตามแผนของตนเองอย่างแม่นยำ (ค่าจริง 1.27 ลลบ.ม./วัน = แผน 1.209 + ท่อส่งน้ำ 0.065) แต่แผนไม่มีกลไกตอบสนองเมื่อน้ำเก็บเกินเกณฑ์ จนวันพายุ (26 ก.ย.) เหลือพื้นที่กันน้ำเพียง 0.6 ล้าน ลบ.ม. จาก 224.9 และถูกบังคับให้ "ปล่อยหนักในจังหวะที่ท้ายน้ำวิกฤตที่สุด"

**การจำลอง (F-SC1)**: หากไล่น้ำเก็บลง URC ตั้งแต่ 30 ส.ค. (ปล่อยเพิ่ม ~8 ลลบ.ม./วัน เพียง 3 วันแรก แล้วดำเนินแผนเดิมทุกประการ) วันน้ำสูงสุด 27 ก.ย. เขื่อนจะต้องระบายจำเป็นเพียง **12.1 ลลบ.ม./วัน (140 ลบ.ม./วิ)** แทน 31.66 (366) — ต่ำกว่า 62% และต่ำกว่าอัตราที่ถูกสั่งให้ลดลงในวันที่ 28 ด้วยซ้ำ — การน้ำท่วมพื้นที่กว้างจะยังเกิดจากฝนอยู่ดี แต่ช่วงน้ำค้างสูงจะสั้นลงอย่างมีนัยสำคัญ

## ส่วนที่ 2: สาเหตุน้ำท่วม (เป้าหมาย 2) — ลำดับเหตุการณ์เชิงเหตุผล

### 3.2 ผลการเทียบ

**(ก) ต่อ Rule Curve**: น้ำเก็บเหนือ URC ต่อเนื่อง 36 วัน (30 ส.ค.–4 ต.ค. ยอดสูงสุดเหนือเกณฑ์ +19 ลลบ.ม. เมื่อ 20 ก.ย.) โดยปล่อยคงที่ 1.27 ลลบ.ม./วัน ถึง 22 ก.ย. — URC โดยนัยคือ "เพดานฤดูฝนที่เก็บได้" เก็บเหนือเพดาน = ใช้พื้นที่กันน้ำหลากที่เขื่อนออกแบบไว้ **[F ต่อข้อเท็จจริง / การตีความว่า "เหนือ URC ต้องระบายทันทีหรือไม่" ขึ้นกับระเบียบ กช. ที่ยังไม่พบ]**

**(ข) ต่อแผนที่ประกาศไว้เอง**: ปฏิบัติตรงแผนเป๊ะ (1.209+0.065 ≈ 1.27 จริง) — **ไม่มีความผิดแผน** แต่แผนไม่มีกลไกระบายลดระดับ แม้ขณะออกแผน (ปลาย ส.ค.) น้ำเก็บเพิ่งทะลุ URC แล้ว **[F]**

**(ค) ต่อผังน้ำลุ่มบางปะกง**: ผังน้ำกำหนดลุ่มสาขาแม่น้ำนครนายกใช้ขอบเขต **น้ำท่วมคาบอุบัติซ้ำ 100 ปี** เป็น "พื้นที่ทางน้ำหลากเพื่อระบายน้ำ (ลร.๑)" ครอบคลุมตำบลส่วนใหญ่ของ อ.เมือง (เขาพระ ดงละคร ดอนยอ ท่าทราย บ้านใหญ่ พรหมณี วังกระโจม ศรีจุฬา ศรีนาวา สาริกา หินตั้ง) — ยืนยันเชิงนโยบายว่าพื้นที่นี้คือทางระบายน้ำหลากตามธรรมชาติของลุ่ม การเกิดน้ำท่วมพื้นที่กว้างเมื่อฝนเกินการออกแบบจึงเป็นไปตามคุณสมบัติของลุ่มน้ำ ผังน้ำ**ไม่มีบทบัญญัติการระบายของเขื่อน** [F]

**(ง) ช่องว่าง**: คำตอบทางกฎหมายว่า "การเก็บน้ำเหนือ URC 36 วันโดยไม่เร่งระบาย ผิดระเบียบหรือไม่" ต้องใช้ระเบียบ กช. ภายใน — เสนอให้ยื่นขอข้อมูลตาม พ.ร.บ.ข้อมูลข่าวสารของราชการ ต่อ กช./สช.9 (แนบเครื่องหมายคำถามใน ANALYSIS_PLAN.md ข้อ B3)

## ส่วนที่ 5: ข้อเสนอแนะเชิงนโยบาย (จากหลักฐานเท่านั้น)

1. **กลไกตอบสนอง URC**: ตารางระบายรายเดือนควรมีเงื่อนไขอัตโนมัติ เมื่อน้ำเก็บ > URC ติดต่อกันเกิน N วัน ต้องเพิ่มการระบายเชิงรุก (แม้หน้าฝน) — เหตุการณ์นี้พิสูจน์ว่าการรอจนอ่างใกล้เต็มทำให้สูญเสียทางเลือกทั้งหมด
2. **การสื่อสารอัตราปล่อยเป็น "ลบ.ม./วินาที + ระดับเปิดบาน ซม."**: เขื่อนเปิดเผยแล้ว (เพจเขื่อนโพสต์ระดับ ซม. ทุกครั้ง) — ควรกำหนดเป็นมาตรฐานสาธารณะและประกาศพร้อมการพยากรณ์อัตราน้ำถึงจุดวัดท้ายน้ำ
3. **พื้นที่ ลร.๑ ของผังน้ำบางปะกงใน อ.เมือง**: การใช้ที่ดินในตำบลที่ระบุควรถูกทบทวนตามข้อบัญญัติผังน้ำอย่างจริงจัง (เป็นทางระบายน้ำหลาก 100 ปีตามกฎหมาย)
4. **เรื่องที่ต้องทำให้จบก่อนสรุปเด็ดขาด**: (ก) ขอระเบียบ กช. + คู่มือเดินเครื่องเขื่อนตาม พ.ร.บ.ข้อมูลข่าวสาร (ข) สอบถามนิยาม Outflow สะสมของกราฟโครงการ (339.872 ณ 4 ต.ค.) ที่สูงกว่าผลรวม API (302.441) อย่างสม่ำเสมอ ~+37 ลลบ.ม. — ไขแล้วบางส่วน: ตัวเลขจริงบนกราฟ ไม่ใช่ OCR ผิด และชุด API ผ่าน mass balance (ดู METHODS.md) (ค) ขอ datum จุดวัด Ny.7 เพื่อแปลงเป็น ม.รทก.
